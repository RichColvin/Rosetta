# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A LinuxCNC configuration (not a compiled software project) for the "Rose Engine Butler" — a control system for ornamental turning lathes (rose engines), built by Colvin Tools / Brainwave Embedded. It uses a Raspberry Pi 5 + Mesa 7i92 (`hm2_eth`) FPGA cards driving up to 10 stepper channels via StepperOnline DM542T drives - 6 from the base box's card, 4 more from the optional expansion box's (see "Two-box progress" below). Details: https://RoseEngineButler.com.

**Tracker:** `docs/REB_Tracker.md` is the one list of what's untested on a machine, what's open, and what was recently settled (since 11 October 2026). Read it at the start of REB work; when you build something that hasn't run on hardware yet, find a problem, or agree a follow-up, add it there (dated), and move items to its Done table when they're settled. Per-machine Claude memory isn't shared between Rich's Pi and Mac, so anything that matters goes in the tracker. Both machines edit it, so `git pull` before changing it and commit to `dev-rich` (then fast-forward `main` if Rich asks) - on 11 October 2026 a Mac commit straight to `main`, made from an older copy, silently dropped three rows the Pi had just added. Ideas not yet being built go in its Planning section.

**File conventions** (since 11 October 2026): each file's header "Version" entries read `x.x - dd Month yyyy` (two-digit day, full month), optionally followed by ` - what changed`, with no programmer's name; `REB_main.py`'s section banners use `# Updated: ver x.x, dd Month yyyy` the same way, and in-file notes like `# Added dd Month yyyy - ...`, `Modified dd Month yyyy`, `Created dd Month yyyy` carry no name either (explanatory mentions such as "Rich's 7i92.xlsx" are fine). Boxed comment headers are 71 columns with `#` in the last (73 in `REB_Tool.tbl`, whose lines start `; `). No tab characters in tracked text files - use spaces (the old tabs were width 4); the exception is the Mesa vendor source `REB_Setup/MesaCard/PIN_REB_34.vhd`, left as Mesa ships it.

**Reserved names** (20 October 2026): `[DISPLAY]PROGRAM_PREFIX` is the repo's `gcode/` folder (gitignored - the operator's own programs), and LinuxCNC searches it for named subroutines (`o<name> call`, looked up as the lowercased `name.ngc`) and user M-code files (`M100`-`M199`) before `[RS274NGC]SUBROUTINE_PATH`, so an operator's file can shadow ours. The user manual tells operators never to name a G-code file starting with "REB"/"reb" (any case) or `M100`-`M199`. So every subroutine REB ships (`REB_Subroutines/`, today `reb_thread.ngc` and `reb_thread_return.ngc`) must be named `reb_...`, and REB doesn't use user M-codes - if it ever needs one, the manual must reserve it first.

There is no build/compile/test step. "Testing" a change means loading the config in LinuxCNC (`linuxcnc REB.ini`) on the actual machine (or a sim) and observing axis/spindle behavior — most of this is real-time motion control tuning, not something that can be verified by static inspection alone.

## Repo vs. local machine state — read this before editing

This repo (`RoseEngineButler`) is the **shared/distributable** config. A sibling directory, `RoseEngineButlerLocal` (NOT part of this git repo, lives at `/home/reuben/linuxcnc/configs/RoseEngineButlerLocal`), used to hold **per-machine local state** that REB.ini/REB.hal referenced by absolute path — as of 4 August 2026 this no longer applies to the HAL customization/tool table files (see below); check before assuming a given per-machine concern still lives there.

- `REB_Custom/REB_Custom.hal` (repo-tracked, relative `[HAL]HALFILE = REB_Custom/REB_Custom.hal` in REB.ini) — end-user HAL customizations.
- `REB_Custom/REB_Tool.tbl` (repo-tracked, relative `[EMCIO]TOOL_TABLE = REB_Custom/REB_Tool.tbl` in REB.ini) — the tool table.

  These two used to live in `RoseEngineButlerLocal/REB_Custom/` (loaded by absolute path) with this repo's own `REB_Custom/` copies serving only as templates/fallback. Rich asked for REB.ini to point at the repo's own copies instead, so as of 4 August 2026 the `RoseEngineButlerLocal` copies (along with the stale `REB_Settings_v1.ini`/`REB_Last_Settings_Path.txt` left over from earlier, already-retired persistence designs, and an unused, never-wired-up `REB_Custom/REB_Shutdown.hal` template) were deleted; `RoseEngineButlerLocal` now holds nothing referenced by REB.ini/REB.hal at all. This does mean end-user HAL additions and the tool table are tracked in git now (a deliberate trade of the old repo/local separation for simplicity) - keep that in mind before committing either file on someone else's behalf.
- `/home/reuben/Documents/REBset_v1.ini` — persisted per-axis stepgen scale, backlash, and PID gain values, plus Measurement System/Max Jog Speed/jog-speed-defaults choices, plus (added for the Axis Selection tab — see below) a `channel_assignments` dict recording which of the 10 roles (8 axis letters or 2 spindles) each of the 10 channels (00-09) currently uses. A `channel_types` sibling dict briefly existed (3–4 September 2026, an independent per-channel TYPE choice) but was retired the same week it shipped — TYPE has been purely letter-derived (`_axis_type_for_letter`: A/B/C angular, everything else linear) ever since, with no UI control that can set it independently (a JSON file despite the `.ini` extension — was hand-rolled-regex-patched XML until 22 August 2026, when it and `Export_Settings`/`Import_Settings`'s `.REBset_v1.ini`-suffixed export files were both migrated to JSON, read/written via a new shared module, `REB_Display/reb_settings_io.py`, imported by `REB_main.py`, `REB_Scale_Persist.py`, `REB_Settings.py`, and `REB_Setup/REB_Generate_Local_Ini.py` — a deliberate exception to those processes' usual "duplicate small constants, don't share code" convention (see "Roles vs. channels" below), since getting settings read/write/legacy-migration logic wrong independently caused real data loss before the fix. A machine still holding the old XML format converts automatically the first time `reb_settings_io.load_settings()` reads it, backing up the untouched original to `REBset_v1.ini.xml-backup` first — see that module's docstring and `docs/settings_file.md`'s top note for the full history and the two real bugs this fixed). Written automatically by `REB_Display/REB_Scale_Persist.py` at shutdown; channel assignments are written immediately by `REB_Settings.py` when the operator changes them. Lives in `~/Documents`, not `RoseEngineButlerLocal`, so it sits alongside the operator-facing `.REBset_v1.ini` export files (Export/Import - see `docs/settings_file.md`) rather than in the repo's per-machine-state sibling directory. (The named `.settings.ini` Save As/Load mechanism `docs/settings_file.md` originally designed has since been retired — see that doc's "RETIRED" notice.)

`sim.var` / `sim.var.bak`, `REB.local.ini`, `REB.local.hal`, `REB_Display/REB_PostGUI_v1.local.hal`, and `REB_Display/__pycache__/` appearing in `git status` are runtime artifacts (all gitignored), not tracked source — don't commit them.

**`REB.local.ini`** (gitignored, lives right next to `REB.ini` in this repo's own directory — see why below) is regenerated on every launch by `REB_Setup/REB_Generate_Local_Ini.py`: a full copy of REB.ini with this machine's persisted Max Jog Speed / General-tab jog-speed values (`DEFAULT`/`MAX`/`MIN_ANGULAR_VELOCITY`, `DEFAULT`/`MIN_LINEAR_VELOCITY` — see `VELOCITY_SETTINGS` in `REB_main.py`) / Measurement System (from `/home/reuben/Documents/REBset_v1.ini`) overlaid onto it. This is the file LinuxCNC is actually launched against (see `REB_Launch.sh`) — never edit it directly, it's overwritten on the next launch.

Why it exists: `[TRAJ]`/`[DISPLAY]` `MAX_LINEAR_VELOCITY` (and its four `VELOCITY_SETTINGS` siblings) and `[TRAJ]LINEAR_UNITS`/`[JOINT_n]UNITS` are read once by LinuxCNC at process startup — before any HAL component or `REB_main.py` runs — so, unlike stepgen scale/PID/backlash (live HAL pins), they can't be corrected mid-session. An earlier version of the Settings tab's Max Jog Speed / Measurement System controls patched these values directly into the tracked REB.ini, which meant a `git pull` of someone else's REB.ini change could silently clobber a machine's own choice. `REB_main.py` only ever writes to `REBset_v1.ini` now; it no longer touches REB.ini at all. Each of the three keys shared between `[DISPLAY]` and `[TRAJ]` (`DEFAULT_ANGULAR_VELOCITY`, `MAX_ANGULAR_VELOCITY`, `DEFAULT_LINEAR_VELOCITY`) is overlaid in both sections with the same value — a deliberate choice, not an oversight, even though `[TRAJ]MAX_ANGULAR_VELOCITY`'s shipped value (36000, an effectively-unlimited trajectory ceiling) differed substantially from `[DISPLAY]`'s (1.0, a sane jog-slider cap) before this feature unified them under one operator-facing control.

Why it must live next to REB.ini and NOT in `RoseEngineButlerLocal`: LinuxCNC treats the directory of whichever ini file is actually passed on its command line as "the configuration directory," and resolves every *relative* path anywhere in that config against it — REB.ini's own `HALFILE = REB.hal`, `POSTGUI_HALFILE = REB_Display/REB_PostGUI_v1.hal`, `PARAMETER_FILE = sim.var`, and even the relative `loadusr python3 REB_Display/REB_Scale_Persist.py` line inside `REB_Shutdown.hal`. Generating `REB.local.ini` into `RoseEngineButlerLocal` broke every one of those (confirmed live: `CANNOT FIND FILE FOR:REB.hal`, and `REB_Scale_Persist.py` not found at shutdown) since that became the new configuration directory. Writing it next to REB.ini keeps every relative path resolving exactly where it always has.

**Axis Selection tab and `REB.local.hal`/`REB_PostGUI_v1.local.hal`**: `REB_Settings.py`'s "Axis Selection" page (a standalone program, not embedded in AXIS — see "GUI layer" below) lets the operator assign any of the 10 roles (`X Z U V W A B C`, `Sp0`, `Sp1` — `Y` excluded, `LATHE=1`) to any of the 10 channels (00-05 = `hm2_7i92.0.stepgen.00`–`.05` on the base card, 06-09 = `hm2_7i92.1.stepgen.00`–`.03` on the expansion card, used only while it's connected) via one combo per channel — widened from the original 6-channels/axis-letters-only version to 8 channels 13 September 2026 (no more spindle channels permanently fixed at 06/07), and to 10 with the two-box work 14 October 2026. No role used twice (flagged live via a per-channel "Duplicate!" warning, `_update_validation_warnings`, which blocks persisting rather than blocking the pick itself); since 19 September 2026 the same check also blocks Sp1 being assigned while Sp0 isn't, since Sp1's speed is always computed as a percentage of Sp0's (`Sp1_Set_Move_Pct`/`_Sp1_Send_Pct` in `REB_main.py`) and has no meaning running alone. TYPE (`Linear`/`Angular`) is purely letter-derived (`_axis_type_for_letter`) and has no independent UI control — a brief exception between 3 and 4 September 2026 was retired the same week it shipped.

The choice is saved immediately to REBset_v1.ini's `channel_assignments` (`_save_channel_assignments`/`_read_persisted_channel_assignments` in `REB_Settings.py`, duplicated in `REB_main.py`, `REB_Scale_Persist.py`, and `REB_Setup/REB_Generate_Local_Ini.py` — see "Roles vs. channels" below) but, like Measurement System/velocity settings above, doesn't take effect until a restart, because it's baked into three files LinuxCNC/HAL only read at startup: alongside `REB.local.ini` (whose `[AXIS_*]`/`[JOINT_n]` `TYPE`/`UNITS` and `[KINS]`/`[TRAJ]`/`[DISPLAY]` coordinate-order keys `REB_Generate_Local_Ini.py`'s `_overlay_axis_assignment` rewrites per the current assignment), that same script's `generate_local_hal_files` regenerates **`REB.local.hal`** and **`REB_Display/REB_PostGUI_v1.local.hal`** (both gitignored, written next to their tracked originals) from the tracked `REB.hal`/`REB_PostGUI_v1.hal`, renaming every net/component-instance name that embeds a role's letter to match (letter-substitution only). `REB.local.ini`'s own `HALFILE`/`POSTGUI_HALFILE` keys are overlaid to point at these generated files instead of the tracked ones (`_overlay_hal_files`) — so, unlike the note below that REB.hal/REB_PostGUI_v1.hal are "not meant to be user-edited," they're now also not what's actually loaded once this feature has ever run: **the *tracked* `REB.hal`/`REB_PostGUI_v1.hal` are templates for the "nothing reassigned yet" case**, read but never written by the generator, and the *generated* `.local.hal` files are what LinuxCNC actually loads. See "Roles vs. channels" below for the naming scheme this relies on.

## Architecture

**Load order or a LinuxCNC session** (see `REB.ini`):
0. `REB_Launch.sh` — the actual desktop-launcher entry point (not `linuxcnc REB.ini` directly). Runs `REB_Generate_Local_Ini.py` to regenerate `REB.local.ini`/`REB.local.hal`/`REB_Display/REB_PostGUI_v1.local.hal` (next to their tracked originals) from REB.ini/REB.hal/REB_PostGUI_v1.hal, then execs `linuxcnc` against `REB.local.ini` (which itself points at the two generated `.local.hal` files — see "Axis Selection tab" above).
1. `REB.ini` — the master config: `[EMC]`/`[DISPLAY]`/`[KINS]`/`[TRAJ]` sections plus one `[AXIS_*]`/`[JOINT_n]` section per axis and one `[SPINDLE_n]` per spindle. Step timing and the fixed per-joint values live here; speed/acceleration limits and PID gains are only *starting* values since each machine's own live in REBset_v1.ini (see "Speed limits in REB Settings" below). The old per-axis `REB_Axes/*.inc` files were merged into REB.ini's `[JOINT_n]`/`[SPINDLE_n]` sections (see git history) and no longer exist.
2. `REB.hal` — loads realtime components (`hostmot2`, `hm2_eth`, `pid`, `orient`, `mux2`, `or2`, `estop_latch`) and wires each joint's stepgen ↔ PID ↔ HAL pins. **Not meant to be user-edited** — and, per "Axis Selection tab" above, not even what's actually loaded once a channel has ever been reassigned (`REB.local.hal` is).
3. `REB_Custom/REB_Custom.hal` — user HAL additions, loaded after REB.hal.
4. `REB_Display/REB_PostGUI_v1.hal` — runs after the GUI loads; wires the gladevcp panel's per-role ENA buttons through a flipflop-based toggle, ANDed with an override pin (`gladevcp.<letter>_Ena_Override`, created by `REB_main.py` at panel startup for every role in `PANEL_INTERNAL_IDS`, set from `REB_Settings.py` via halcmd across the process boundary), into each role's actual enable net. Same "template, not what's actually loaded" caveat as REB.hal above. Every one of the 8 axis letters has this chain (as of 19 September 2026 - B/C were the last two to get theirs); Sp0/Sp1 use a simpler variant with no `-estop-and` stage, since their stepgen enable is already wired straight to `machine-is-on` in REB.hal.
5. `REB_Shutdown.hal` — runs `REB_Display/REB_Scale_Persist.py` to persist live stepgen position-scale values back into `/home/reuben/Documents/REBset_v1.ini`.

**Axis/joint map**: joint numbers aren't fixed. At each launch `REB_Generate_Local_Ini.py`'s `RoleLayout` numbers the axis letters on channels in use 0, 1, 2, ... in `JOINT_NUMBER_CANONICAL_ORDER` (X Z B U V W A C), skipping any not assigned to a channel in use, and the spindles in use become LinuxCNC spindles 0 and 1 (`SPINDLE_NUMBER_CANONICAL_ORDER`: Sp0, Sp1). With the default roles that gives X=0 Z=1 B=2 W=3 without the expansion box, and X=0 Z=1 B=2 U=3 V=4 W=5 A=6 C=7 with it. `Y` is excluded (`LATHE=1`). The tracked REB.ini/REB.hal describe X Z B U V W (`JOINTS = 6`, `trivkins coordinates=XZBUVW`) and are only templates - the generator rewrites the joint sections and the `[KINS]`/`[TRAJ]`/`[DISPLAY]` joint, spindle and coordinate keys to match each launch's layout. Channel/plug wiring is fixed; which role a channel plays is the operator's choice - see "Roles vs. channels" below. W used to have no PID (open-loop stepgen, fed straight from `joint.5.vel-cmd` — fine for a hand-jogged-only slide, but silently produced zero motion on any G-code/MDI-commanded move, which only drives `motor-pos-cmd`, not `vel-cmd`); fixed 4 September 2026 to a normal PID-closed loop, matching every other reassignable channel, once W became reassignable to letters needing real G-code-commanded indexing.

**Limit switches** (added 28 September 2026): 6 GX-12 limit jacks - 1-3 on the base box, 4-6 on the expansion box (since 14 October 2026; used only while it's connected) - each taking a normally-closed switch and each optionally left empty. On REB Settings' Inputs, Outputs, and Sounds page (the Axis Selection page until 11 October 2026; `Limit_Jack_N_Axis`, `LIMIT_JACKS` in `REB_Settings.py`) each jack is set to "Not used", or for an axis letter: "(both ends)" (a switch at each end wired in series - LinuxCNC can't tell which end tripped, so recovery needs AXIS's Override Limits), "min" (negative end only) or "max" (positive end only). A min/max pair on one axis (e.g. both ends of a curvilinear slide - Rich's motivating case) lets LinuxCNC know which end tripped, so the operator can jog away without Override Limits. Persisted in REBset_v1.ini's `limit_switches` dict: jack -> `"B"` (both), `"B min"`, `"B max"`, or `""`; absent = none used, the default (a pre-min/max `"B"` entry still means both ends). Each combo only offers axes currently assigned to a channel (`_rebuild_limit_jack_combos`) - a jack whose axis loses its channel (or a persisted value naming an unassigned axis) is switched to "Not used" and saved, with an orange "<letter> not assigned - cleared" notice; this only happens once the channel assignment is valid, so a transient "Duplicate!" mid-rearrangement can't wipe a jack. Two jacks on the same axis block saving unless they're a min/max pair ("Duplicate!" for identical choices, "Conflict!" for e.g. both-ends plus min). REB.hal doesn't touch any joint's `neg-lim-sw-in`/`pos-lim-sw-in`; `REB_Generate_Local_Ini.py`'s `_limit_jack_hal` wires them per in-use jack using this launch's joint numbers - net `<letter>-limit-sw` (both pins), `<letter>-limit-min` (neg) or `<letter>-limit-max` (pos), sourced from the jack's card's `hm2_7i92.N.gpio.NNN.in` - just before REB.local.hal's closing banner, and skips (with a console message) any jack whose axis isn't assigned or that conflicts with a lower-numbered jack. `_parse_limit_value`/`_limit_ends_conflict` are duplicated in both files. Jack -> pin map is `LIMIT_JACK_INPUT` there (jacks 1/2/3 -> `hm2_7i92.0` I/O 002/006/010, i.e. Input0/1/2 on P2 pins 3/7/13; jacks 4/5/6 -> the same I/O on `hm2_7i92.1` - a placeholder until the PCB wiring is final). Uses the GPIO's `.in` (NC switch to ground, 7i92 pull-up makes an open switch read true = limit hit) - polarity unverified on the machine as of this writing. Since 08 October 2026 REB Settings' Limit Switch Type radios (`Limit_Switch_NC`/`_NO`, a row under Limit Jack 1; REBset_v1.ini `limit_switch_type`, `"NC"`/`"NO"`, seed and absent = `"NC"`) pick NC or NO for all six jacks - NO reads `.in_not` instead. NC is strongly recommended (a broken wire or unplugged NC switch reads as tripped; an NO one silently stops working), said in the Limit Switches section of the page's right-hand notes column and in the radios' tooltips. **E-stop button** (added 28 September 2026): optional, on a GX-16/2 plug - a normally-closed button between P1 pin 21 (7i92 I/O 31, `hm2_7i92.0.gpio.031.in`) and ground. REB.hal always runs LinuxCNC's E-stop chain through `estop-latch.0` (`user-enable-out` -> `ok-in`, `user-request-enable` -> `reset`, `ok-out` -> `emc-enable-in`), replacing the old plain `user-enable-out` -> `emc-enable-in` loop; with no fault source it behaves the same as that loop. REB Settings' `Estop_Button_Connected` checkbox (REBset_v1.ini `estop_button`, absent = false) makes `REB_Generate_Local_Ini.py`'s `_estop_button_hal` add `net estop-button <= hm2_7i92.0.gpio.031.in => estop-latch.0.fault-in` - pressed/broken/unplugged reads high and latches E-stop until released and reset with F1. Deliberately optional because an empty plug would otherwise hold the machine in E-stop. Input pin is `ESTOP_BUTTON_INPUT` there; kept away from the limit jacks' Input0-2 so more limit jacks can be added next to them.

**Plain GPIO instead of InM** (28 September 2026): REB.hal loads the card with `num_inms=0`, so the firmware's InM module (Input0-7, hardware-debounced inputs) is off and those pins are plain GPIO (`hm2_7i92.0.gpio.NNN.in`/`.out`, NNN = the 3-digit I/O number). That was needed to get a third output pin for the signal tower without rebuilding the FPGA firmware; the limit jacks and E-stop lose the InM debounce filter, which doesn't matter for them. Don't reintroduce `inm.00.*` pin names.

**Signal tower** (added 28 September 2026): optional, on a GX-12/4 plug - green light, red light and a buzzer, each switched by a relay from one GPIO output: green = P1 pin 25 (I/O 033), red = P2 pin 25 (I/O 016) - the firmware's two unassigned pins - and buzzer = P1 pin 13 (I/O 027, formerly Input6, freed by `num_inms=0`; Input3 on P2 pin 21 is left for the next limit jack). `SIGNAL_TOWER_OUTPUT` in `REB_Generate_Local_Ini.py`. REB Settings' `Signal_Tower_Connected` checkbox (REBset_v1.ini `signal_tower`, absent = false) makes `_signal_tower_hal` set those pins `is_output` and wire: green <- a `logic` OR (`tower-green-or`) of: NOT `halui.program.is-idle` (a program or MDI command running - Sync Move, Threading, axis indexing), each active spindle's `spindle.<n>-cw`/`-ccw` (running - Run Operation/M3/M4 finish as MDI commands at once while the spindle keeps turning, which is why is-idle alone left green dark, found live 05 October 2026), and each active spindle indexing (`spindle.<n>-pos-mode-enable` AND NOT its `orient-done`/`orient.1-done` - M19 leaves orient enabled afterwards to hold position, so enable alone would keep green lit); the NOTs are 2-input `logic` NANDs with both inputs on one signal; red <- a latch on every active joint's `joint.N.f-errored` plus every in-use limit jack's net (OR'd by `tower-fault-or`) - LinuxCNC does NOT hold f-errored, it clears as the machine turns off (found live 05 October 2026: red never lit), and a limit trip can be just as brief (switch closes again once the axis stops - found live the same day: buzzer sounded, red didn't stay lit), so `tower-red-hold` is a `oneshot` with a practically endless pulse (`SIGNAL_TOWER_LATCH_SECONDS`) acting as a latch, reset by `tower-on-edge`'s short pulse when `machine-is-on` rises (F2) - OR'd (`tower-red-or`, only created when limit jacks are in use) with every in-use limit jack's net (`<letter>-limit-sw`/`-min`/`-max`), so a switch still open after F2 keeps red lit until the axis is moved off it - Rich's chosen "error" definition (following-error fault or limit hit; not E-stop, not program aborts); buzzer <- a `oneshot` (`tower-buzz`) pulsing `SIGNAL_TOWER_BUZZER_SECONDS` (3 s) on red's rising edge. The relays switch on when their input is pulled low - the REB standard, fixed as `SIGNAL_TOWER_ACTIVE_LOW` (the relays are on Chuck's REB circuit board and home-built systems must match; a REB Settings checkbox for it existed 08-11 October 2026 and was removed) - the 7i92's pull-ups hold every pin high whenever LinuxCNC isn't driving it (boot, after exit), so an active-high board would light/sound everything then. With the tower off, the three pins stay inputs. `not`/`and2`/`or2` are already loaded elsewhere under fixed names/counts, which is why this uses `logic`/`oneshot` and GPIO inversion instead.

**Attention beeps** (added 06 October 2026): 3 short beeps (`DONE_BEEPS`, 0.2 s on/off - deliberately unlike the tower's steady 3 s fault siren) when a G-code program, a Sync Move Run Operation or a Cut Thread finishes normally; 2 (`PAUSE_BEEPS`) when a program stops at M0/M1/M60. **Program progress bar** (added 20 October 2026, Rich's design): `Program_Progress` (a GtkProgressBar in MainGrid row 20, columns 4-9, left of the Sync Move buttons) shows "Program 42%" (plus "(paused)") while a G-code program runs, then "Program done in ..." / "Program stopped at 42%" until the next run or program load. A run whose first line isn't among the first `PROGRESS_START_MOVES` moves (Run From Line) shows "Started part way". Driven from `_poll_program` (`_progress_start`/`_progress_update`/`_progress_end`). Run Operation, indexing and the Return moves deliberately don't show it (Rich, 20 October 2026). the bar keeps its space with `set_child_visible` so the panel doesn't resize. **Roles vs. channels**: a **role** (one of the 8 axis letters or 2 spindle ids, `CHANNEL_ROLES`) is a stable identity that never changes — it's what G-code axis words use, what every `.ui` file's widget ids are built from (`X_Set_Scale`, `gladevcp.X_Ena_Override`, `gladevcp.X_ENA-light`, …), and what every HAL net name that embeds a letter uses (`x-enable`, `pid.x`, …). A **channel** (00-09: `hm2_7i92.0.stepgen.00`–`.05` on the base card, `hm2_7i92.1.stepgen.00`–`.03` on the expansion card) is just physical wiring — which role currently drives a given channel is the one thing that's dynamic, recorded in REBset_v1.ini's `channel_assignments` and resolved fresh at each launch by `REB_Setup/REB_Generate_Local_Ini.py`, which renames every letter-embedding net in `REB.hal`/`REB_PostGUI_v1.hal` to match (see the Axis Selection tab section above) — so a role's own net names (`pid.x`, `x-enable`, …) always mean "whichever channel currently plays role X," never a fixed channel number. `CHANNEL_DEFAULT_ROLE` (channel id → its default role) lives in `reb_settings_io.py` since 14 October 2026 (before that it was duplicated across `REB_Settings.py`, `REB_main.py`, `REB_Scale_Persist.py`, and `REB_Setup/REB_Generate_Local_Ini.py`, per this codebase's "duplicate small constants/logic across independent scripts" convention) - it's the fallback used to seed a role's channel the first time REBset_v1.ini is read, and (via each file's own `_read_persisted_channel_assignments`) the source of truth for which roles are currently assigned to *some* channel at all, which gates whether a role's main-panel row is usable (`_load_panel_axis_controls` in `REB_main.py`) and whether its widgets on the Axis Selection tab warn about a bad assignment.

Until 19 September 2026, `REB_main.py`'s own copy of this model lagged behind the rest of the codebase: it still worked in terms of a fixed set of 6 "internal ids" (channel *slots*, not roles) that could be renamed to show any letter, computed fresh each launch (`CURRENT_LETTER`/`CURRENT_TYPE`) and used to swap each panel row's image/color/adjustment ranges at runtime - a design that predated the 13 September 2026 generalization to 8 channels/10 roles and was never updated to match, leaving REB_Panel_v1.ui's main panel understanding only 6 of the 8 channels and unable to show C at all (A only got a bare ENA button 18 September, borrowing B's other widgets underneath - see git history for the full story). REB_Panel_v1.ui was rebuilt that day so every one of the 10 roles has its own permanent, independent row with its image/color/type-correct Feed-Idx ranges already baked in statically (no more per-row reassignment to account for), and `REB_main.py` was correspondingly simplified to match the same "role vs. channel" model `REB_Settings.py`/`REB_Scale_Persist.py`/`REB_Generate_Local_Ini.py` already used: `CURRENT_LETTER`/`CURRENT_TYPE`/the old "internal id" framing are gone from `REB_main.py` entirely now - a role's G-code axis word, HAL net names, and TYPE (`_axis_type_for_letter` - A/B/C angular, everything else linear, purely letter-derived since the brief independent-TYPE experiment above was retired) are simply computed directly from the role's own fixed letter. `_load_panel_axis_controls` now does exactly one thing: grey out (`set_sensitive(False)`) every widget belonging to a role not currently assigned to any channel (`AXIS_ROW_FIELDS`/`SPINDLE_ROW_FIELDS`).

**The side panel and the two embedded tabs are separate OS processes, not just separate `Gtk.Builder`s in one process.** `REB_Panel_v1.ui` is loaded via `[DISPLAY]GLADEVCP` - which AXIS also runs as its own `gladevcp -x <window>` process, embedded in its window (seen in `ps` 20 October 2026; earlier notes here said in-process) - and Help/License are each launched independently via their own `halcmd loadusr -Wn <name> gladevcp ... -u REB_Display/REB_main.py <file>.ui` (`EMBED_TAB_COMMAND` in REB.ini) — three separate Python interpreters all running the same `REB_main.py` module, each with its own `HandlerClass` instance and its own `self.builder`. The `if self.builder.get_object("X_ENA") is None: return` guards scattered through `REB_main.py` exist to let each instance recognize whether it owns the main panel's widgets and no-op if not — but this also means one instance can never directly read or set another instance's live widgets. The only channel between them is going through disk (`REBset_v1.ini`) or HAL pins; anything that needs to look "live" across that boundary but isn't backed by one of those has to fall back to telling the operator to restart LinuxCNC, mirroring the existing `_show_restart_required_popup` pattern already used for Measurement System/velocity settings.

**Tuning comments**: many `[JOINT_n]` blocks in REB.ini carry long inline comments explaining *why* a PID/STEPGEN value was changed (e.g. STEPGEN_MAXACCEL vs MAX_ACCELERATION ordering, FF1 vs P/I windup). When adjusting tuning values, preserve or update these comments rather than deleting them — they record hardware-derived ceilings (step timing → max steps/sec) that aren't otherwise obvious from the number alone.

**Version reporting** (23 October 2026, Rich's idea - wants to see who's still using the system and what version, for support calls): `REB_Setup/REB_Report_Version.py`'s `report_version()` runs every update, from `REB_Update_Settings.py`'s `main()` (not a `ONE_TIME_STEPS` entry - those self-skip once satisfied, this must send every time). It identifies the machine by its own Raspberry Pi hardware serial (`/proc/cpuinfo`'s `Serial` line, falling back to `/sys/firmware/devicetree/base/serial-number`) - unique with no coordination needed, Rich's answer to "how do we stop a self-built machine's S/N colliding with a shipped one's": don't rely on a human-picked number for identity at all. The human-friendly serial number ("S/N 4", for talking to support) is reported alongside it as a label only, from `~/.config/REB/serial` if set - it never needs to be unique, since the hardware ID is what actually disambiguates. `REB_Setup/REB_Set_Serial_Number.sh` asks for it (skippable; asks again next update if skipped, no separate "declined" marker - it just checks whether the file already holds a value), run from the Trixie installer's Step 11 and, for already-built machines, from `ONE_TIME_STEPS` (same self-skip pattern as the folder shortcuts). The report lands on `support.roseenginebutler.com`, not `manual.roseenginebutler.com` (the user manual) - Rich's call. `REB_Report_Version.REPORT_URL` points at `https://support.roseenginebutler.com/reb_report.php`, a small PHP script (not in this repo - drafted into `~/Downloads` for Rich to deploy by hand, same as the PmWiki page drafts) that appends each POSTed report to a server-side `reb_reports.jsonl`; `send_report` always logs locally to `~/.config/REB/report_log.jsonl` too, win or lose, but only ever sends the report built THIS run - a failed POST doesn't get retried from the log (a possible later addition once we've seen how often that actually happens). A companion `reb_report_view.php` (same directory, also drafted into `~/Downloads`) shows the server-side log as an HTML table, one row per machine (latest report wins, newest check-in first) - protected by HTTP Basic Auth (`.htaccess`/`.htpasswd`, also drafted; user `REBmachines`) since it's the same fleet data the `.jsonl`/`.htpasswd` direct-access block (403, confirmed) was added to keep private. The version reported is read straight out of `REB_Panel_v1.ui`'s "REB O/S ..." label (regex, not a GTK load) rather than kept as a separate copy that could drift from the five hand-updated labels. Verified end-to-end 23 October 2026: a real report POSTed from Rich's Pi landed in the live server log, the view page correctly requires login, and both direct-access blocks hold - not yet run through a real install or a real `REB_Update.sh` on a second machine - see the tracker.

**`REB_Checkout.sh` / `REB_Setup/REB_Checkout.py`** (added 18 October 2026, `two-box` branch) - bench checkout of a newly built system with a test motor on every channel, run in a terminal. Backs up `~/Documents/REBset_v1.ini` into the run folder (`~/Documents/Checkout/<serial>_<date>/`), writes test settings (scale = one motor turn per unit/360 degrees from `--steps-per-rev`, default 6400; safe speeds; limit jacks and E-stop off), runs the generator, points `REB.local.ini`'s `OPEN_FILE` at a generated `pass_<A|B>.ngc`, runs `linuxcnc` and waits, then asks Pass/Fail/Skip per channel into `checkout_log.txt`. Pass A = default roles; pass B = every role moved `PASS_B_SHIFT` (3) channels along (within 00-05 on a base box, across all 10 with the expansion box). The program turns channel N's motor N+1 times each way, indexes each spindle in quarter turns (`M19`), then moves every axis together under `G93`, with `M0` + `(MSG,...)` before each step; `G8` so X isn't halved by lathe diameter mode. The original settings file is copied back in a `finally` (Ctrl+C, SIGTERM/SIGHUP, generator refusal); `~/Documents/REB_Checkout_restore.json` names the backup while test settings are in place, so a run cut off by a power cut is offered a restore at the next start. `--dry-run` writes the files only (tested that way on the Mac, plus the generator against each pass's settings and the restore paths with LinuxCNC stubbed out). Untested on a machine as of this writing.
