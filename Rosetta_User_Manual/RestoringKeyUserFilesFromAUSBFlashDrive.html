Restoring Key User Files from a USB Flash Drive

On this page

  • Before you start
  • Restoring a backup
  • After the restore finishes: the USB flash drive is ejected
  • What the restore does not change
  • A backup from a different machine

The Restore from USB command copies a backup made by Back Up to USB from a USB flash drive back onto the Raspberry Pi. Use it, for example, after the Raspberry Pi's memory card has been replaced, or to move your own files onto a new Rosetta system.

It puts back the same files Back Up to USB copies: your settings files, your gcode programs, your HAL additions and tool table, and your subroutines and user M-codes. See What Gets Copied for the full list.

Before you start

  • Do not run Restore from USB while LinuxCNC is running. LinuxCNC saves its settings as it closes, which would undo the restore. Close LinuxCNC first. (Rosetta Settings cannot be opened while LinuxCNC is running anyway, and Restore from USB checks again before it starts.)
  • Do not remove the USB flash drive while the restore is running. Wait until Rosetta says it is safe to remove it.

Note: Every file the restore replaces is first copied to the folder /home/reuben/Documents/Before_Restore, in a folder named with the date and time of the restore. If you restore the wrong backup, your previous files are still there.

Restoring a backup

  1. Plug the USB flash drive that holds the backup into the Raspberry Pi.
  2. Open the Rosetta Settings program.
  3. Click on File at the top left corner of the Rosetta Settings window.
  4. Click on Restore from USB... The Restore from USB window opens.
  5. Under USB stick, pick the USB flash drive (if more than one is plugged in).
  6. Under Backup, pick the backup to restore. Each backup is listed by the date and time it was made, newest first. The window shows how many files of each kind the backup holds.
  7. Click Restore. A box lists what will be replaced. Click Restore again to go ahead, or Cancel to stop.
  8. Wait for the Restore complete box, then click OK. The USB flash drive is ejected for you, so it can be removed (see After the restore finishes below).
  9. Rosetta Settings closes by itself. Open it again to see the restored settings.

Note: Rosetta Settings closes after a restore so that it cannot save the settings it was showing over the ones just restored. If you have changed any Scale, speed, acceleration or PID values without saving them, Restore from USB asks first whether to save them.

After the restore finishes: the USB flash drive is ejected

When the restore finishes, Rosetta ejects the USB flash drive. Ejecting means the Raspberry Pi has finished with the flash drive and has disconnected from it, so that it is safe to pull out. The flash drive is still plugged in, but the Raspberry Pi can no longer use it: it no longer shows in the File Manager, or in the Back Up to USB or Restore from USB windows.

  • Do not pull the USB flash drive out while the restore is running. Wait until Rosetta says It is now safe to remove the USB stick.

To use the USB flash drive again - for example, to make another backup, to restore a backup, or to copy a gcode program from it - you have to take it out and put it back in:

  1. Pull the USB flash drive out of the Raspberry Pi.
  2. Wait about 5 seconds.
  3. Plug the USB flash drive back into the Raspberry Pi.
  4. Wait a few seconds for the Raspberry Pi to find it. A File Manager window may open showing what is on the flash drive; you can close that window.

The USB flash drive can now be used again.

Note: If Rosetta says The stick could not be ejected automatically, eject it yourself before pulling it out: open the File Manager, and in the list on the left side of its window, click the eject symbol (⏏) next to the USB flash drive's name. When the flash drive's name disappears from the list, it is safe to pull it out.

What the restore does not change

  • Files on the Raspberry Pi that are not in the backup are left as they are. For example, a gcode program you saved after the backup was made is kept.
  • Backups made before Rose Engine Butler was renamed Rosetta (in a folder named REB_Backup on the USB flash drive) can be restored too. Their old file names are changed to the new ones as they are copied.

A backup from a different machine

If the backup's axis selection (which axis uses each plug) or expansion box setting is different from this machine's, the Restore from USB window says so in red, listing each difference - for example, Channel 04: C here, B in the backup.

  • Do not restore a backup from a machine set up differently unless you mean to. The restore copies that machine's axis selection along with its other settings. After restoring, check the Axis Selection tab in Rosetta Settings, and change it to match how this machine's motors are plugged in, before you start LinuxCNC.
